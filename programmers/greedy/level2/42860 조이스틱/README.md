## **💡 접근 및 설계**

상하로 이동하는 거랑, 좌우로 이동하는 것의 최솟값 구하는 방법을 각각 구한 후 합한다.

상하 이동은 min(target 알파벳, - ‘A’, len(name), target 알파벳)

좌우 이동은 각 지점 `i`(=A 구간 직전 위치)와 `nxt`(=그 A 구간 이후 첫 non-A 위치)에 대해 세 가지를 비교: (AI 도움)

1. **`l-1`** — 안 꺾고 그냥 오른쪽 끝까지 쭉 가기 (기본값)
2. **`2*i + (l-nxt)`** — 오른쪽으로 `i`까지 갔다가 → 0으로 되돌아옴(`2*i`) → 왼쪽 wrap으로 `nxt`까지(`l-nxt`)
3. **`i + 2*(l-nxt)`** — 왼쪽 wrap으로 `nxt`까지 갔다가 → 0으로 되돌아옴(`2*(l-nxt)`) → 오른쪽으로 `i`까지(`i`)

### **🗒️ 최종 제출 코드**

```py
def solution(name):
    answer = 0
    l = len(name)

    # ===== 1. 상하 이동 (알파벳 회전) 비용 =====
    # 모든 칸이 'A'에서 시작하므로, 각 칸을 목표 알파벳으로 바꾸는 최소 횟수를 전부 더한다.
    # 위로 올리는 경우 : tar - 'A'      (A -> B -> ... -> tar)
    # 아래로 내리는 경우: 'Z' - tar + 1  (A -> Z -> ... -> tar, 순환 이용)
    # 둘 중 짧은 쪽을 선택
    for i in range(l):
        tar = ord(name[i])
        answer += min(tar - ord('A'), ord('Z') - tar + 1)

    # ===== 2. 좌우 이동 (커서 이동) 비용 =====
    # 커서는 0번 위치에서 출발.
    # 중간에 연속된 'A' 구간은 방문할 필요가 없으므로,
    # 그 구간을 건너뛰고 반대편에서 접근하는 게 이득일 수 있다.
    # 따라서 "어디서 꺾을지"를 모든 지점에 대해 시도해 최솟값을 찾는다.

    mn = l - 1  # 기본값: 안 꺾고 그냥 오른쪽 끝까지 쭉 가는 경우

    for i in range(l):  # i = 오른쪽으로 여기까지 처리하고 꺾겠다는 지점
        # i 바로 뒤에서부터 연속된 'A'를 건너뛰어,
        # 아직 수정이 필요한(= 'A'가 아닌) 첫 번째 위치를 찾는다.
        nxt = i + 1
        while nxt < l and name[nxt] == 'A':
            nxt += 1
        # nxt = i 뒤에 처음 나오는 non-A 위치 (없으면 l)

        # 세 가지 전략 중 최솟값으로 갱신
        # [1] mn            : 지금까지의 최솟값 (초기값은 안 꺾고 끝까지 가기)
        # [2] i*2 + (l-nxt) : 오른쪽 먼저 처리
        #                     0 -> i 이동(i) + i -> 0 복귀(i) = 2i
        #                     이후 0에서 왼쪽 wrap으로 마지막 칸 점프 후 nxt까지 = (l-nxt)
        # [3] i + 2*(l-nxt) : 왼쪽(wrap) 먼저 처리
        #                     0 -> wrap -> nxt 이동(l-nxt) + nxt -> 0 복귀(l-nxt) = 2(l-nxt)
        #                     이후 0 -> i 오른쪽 이동 = i
        # [2]와 [3]의 차이는 "어느 쪽을 먼저 처리하고 왕복하느냐".
        # 왕복(2배 비용)은 짧은 구간에 대해 하는 게 이득이라 둘 다 계산해 비교한다.
        mn = min([mn, i*2 + (l-nxt), i + 2*(l-nxt)])

    # ===== 3. 상하 비용 + 좌우 최소 비용 =====
    answer += mn
    return answer
}
```

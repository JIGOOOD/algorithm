## **💡 접근 및 설계**

주어진 복잡도 안에 풀 수 있는 방법이 안 떠올라 AI와 함께 풀었다.

## **✏️ 알고리즘 풀이**

```
[입력값의 정의역]
1 <= n, m <= 100,000
1 <= x <= n
1 <= y <= m
1 <= k <= 100
```

### **시간 복잡도**

우선 변수의 범위가 위와 같으므로, n*m 격자는 1억이 넘어 메모리, 시간 모두 초과한다. 그래서 순수 n* m 격자를 사용할 수 없다.

이에 나이트가 이동할 수 있는 범위를 생각해보자. 나이트는 최대 행, 열 2칸씩 이동할 수 있다. 그럼 총 k번 이동한다고 할 때, 행, 열 2k칸씩 이동할 수 있다. 즉, 나이트는 (4k+1)^2 격자 내에서만 움직이는 셈이다 (시작위치 + 앞뒤 2k씩). 이는 약 천육백만이므로 복잡도를 초과하지 않는다.

### **오프셋 매핑**

시작 값이 x, y라 하자. 이는 1-indexed이다. 그러므로 0-indexed로 바꿔줘야 한다.

그래서 나이트가 이동하는 좌표를 오프셋을 적용하면

(nx - (x-1) + offset, ny - (x-1) + offset)이 된다. 시작 점은 격자의 중앙인 (2k, 2k)이다.

### **K번 이동하여 도착할 수 있는 칸**

1. "나이트 한 번 이동은 (행+열)의 홀짝을 항상 바꿉니다"

   나이트의 8가지 이동을 보면 행 변화량과 열 변화량이 항상 {1, 2} 조합입니다. 그러니 **행+열의 변화량은 항상 ±1±2 → 절댓값이 1 또는 3, 즉 무조건 홀수**입니다.

   (0,0)에서 시작하면 행+열 = 0 (짝수).
   - (1,2)로 가면 행+열 = 3 (홀수)
   - (2,1)로 가면 행+열 = 3 (홀수)

   어디로 가든 짝→홀입니다. 한 번 더 가면 홀→짝. 즉 **매 이동마다 홀짝이 반드시 뒤집힙니다.** 제자리에 머무는 선택지가 없으니 예외가 없습니다.

   체스판의 흑백 칸 색이 바로 이 행+열의 홀짝입니다. 나이트는 움직일 때마다 색이 바뀌죠.

---

2. "어떤 칸에 도달하는 모든 경로의 길이는 홀짝이 같습니다"

   시작칸의 홀짝을 S, 목표칸의 홀짝을 T라고 합시다. 이동 한 번에 홀짝이 한 번 뒤집히므로, t번 이동 후의 홀짝은 "S를 t번 뒤집은 것"입니다.
   - t가 짝수 → 홀짝이 S 그대로
   - t가 홀수 → 홀짝이 S의 반대

   그러니 T에 도착하려면:
   - S와 T가 같으면 → **t는 무조건 짝수**
   - S와 T가 다르면 → **t는 무조건 홀수**

   경로를 어떻게 잡든, 3번을 가든 17번을 가든 상관없습니다. 도착 칸의 색이 이동 횟수의 홀짝을 강제로 결정합니다. **홀짝이 안 맞으면 절대 불가능**입니다.

---

3. "재방문 허용 → 2씩 낭비 가능"

   목표 칸까지 최단으로 3번이면 가는데 k=7이라면? 4번이 남습니다.

   버리는 방법: 아무 인접 칸으로 갔다가 바로 되돌아옵니다. **한 왕복 = 2번 소모, 위치는 그대로.** 왕복 두 번 하면 4번 소모. 그래서 3 + 4 = 7번에 정확히 그 칸에 서 있을 수 있습니다.

   낭비 단위가 항상 2라서, **d번에 갈 수 있는 칸은 d, d+2, d+4, d+6, ... 번째에도 갈 수 있습니다.** 1번은 못 버립니다. (문장 2와 정확히 같은 얘기를 다른 각도에서 본 겁니다.)

---

4. 결론 공식

   > 어떤 칸이 정확히 k번으로 도달 가능 ⇔ d ≤ k 이고 d ≡ k (mod 2)
   - **d ≤ k**: 최단거리보다 적게는 못 갑니다. 3번 걸리는 칸을 2번에는 못 가죠.
   - **d ≡ k (mod 2)**: d와 k의 홀짝이 같다는 뜻. 남는 k−d가 짝수여야 왕복으로 다 버릴 수 있으니까요.

   `d ≡ k (mod 2)`는 그냥 `d % 2 == k % 2`입니다.

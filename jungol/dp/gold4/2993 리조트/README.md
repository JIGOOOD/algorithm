## 💡 접근 및 설계

"아직 정산 안 된 첫날을 뭘로 커버할까"를 반복 선택하는 문제. 단, 쿠폰이라는 두 번째 재화가 있어 축이 하나 더 필요.

### ✏️ 알고리즘 풀이

1. 2차원 dp
   dp[i][c] = i일까지 정산 완료 + 쿠폰 c장 보유 시 최소 비용
   - 왜 쿠폰이 상태에 들어가는가?
   - 비용 외에 미래 선택(교환 가능 여부)을 바꾸는 유일한 정보라서. 상태 = 미래 결정에 필요한 최소 정보.
   - 왜 "티켓 잔여 커버일" 축은 없는가?
   - 티켓 전이를 점프로 처리해서 "커버 진행 중"인 중간 상태 자체가 안 생김. 3차원 → 2차원 절약.
   - 초기화: dp[0][0] = 0 (아무것도 안 함), 나머지 inf = 도달 불가 표시.

2. 전이 (push) — dp[i-1][c]에서 i일을 처리하는 방법을 전부 min으로 뿌림
   - 하루권: dp[i][c] + 10000
   - 3일권: dp[min(i+2,n)][c+1] + 25000 → i~i+2 통째로 점프
   - 5일권: dp[min(i+4,n)][c+2] + 37000
   - 쿠폰: c≥3 → dp[i][c-3] + 0. "가격이 쿠폰 3장인 하루권"으로 취급하면 별도 처리 불필요.
   - 못 가는 날: dp[i][c] 무료 통과만.
   - 왜 min(·, n) 클램프?
   - 방학 밖 커버는 무가치 → 전부 "n일 완료"로 접음. 배열 밖 접근 방지 + 완주 경로가 dp[n] 한 행에 수렴.
   - 점프 구간에 낀 못 가는 날은?
   - "기간을 모두 이용할 필요 없음" 조건 덕에 그냥 커버에 포함시켜도 됨. 자동 처리.

3. 답
   min(dp[n][0..54])
   - 왜 c 전체를 훑는가?
   - 완주 상태가 남은 쿠폰 수별로 흩어져 있고, 방학 끝나면 쿠폰은 무가치라 비용 최소만 취함.

알고 보니 누적합 문제였다. 이로써 내가 감이 심하게 떨어졌음을 느꼈다. “누적합”이라는 용어가 낯설게 느껴졌다.

그래서 AI의 도움을 받아 풀었다.

### **✏️ 알고리즘 풀이**

누적합의 나머지를 이용해서 문제를 풀 것이다. arr = [1, 2, 3, 4, 5]라면, 누적합 sum = [1, 3, 6, 10, 15]다.

여기서 sum[j] - sum[i]는 (i, j]까지의 합이다. 즉 i의 범위는 매번 제외된다. 그래서 0-indexed를 사용하면 안된다. 그렇게 되면 처음 입력되는 값(0번째 인덱스)은 항상 구간에 포함되지 않게 된다. 따라서 1-indexed를 따른다.

나머지 배열이 r[7]이라고 하면, r[0]은 항상 0이다. 왜나하면, 처음 입력되는 값을 항상 고려해야 하기 때문이다. 그래야 나중에 나머지가 0인 애가 나와도 첫번째 값까지 고려해서 올바르게 계산할 수 있다.

우리는 순차적으로 누적합을 구하고, 그 나머지가 무엇인지 판별할 것이다. 그리고 sum[j] - sum[i]는 (i, j]까지의 합이라는 원리에 따라, 현재 나머지에서 처음 등장한 나머지를 뺀 값이 최대 길이임을 이용해서 풀이한다.

그 이유는 다음과 같다. 만약 하나의 수가 7a+r이 나머지고 다른 수가 7b-r이라면, (7b-r) - (7a-r) = 7(b-a)이다. 즉 나머지가 같은 값끼리 제외하면 항상 7의 배수가 된다는 것이다.

1. 나머지 배열을 선언한다. r[0] = 0으로 한다.
2. 매 입력에 따라, 누적 합을 구한다. sum[i] = 0~i까지의 id 합. (근데 매번 sum[i-1]만 참조하므로 그냥 int bf 변수 하나 선언해도 된다. 나는 그렇게 했다.)
3. 나머지가 처음 등장하는 것이라면 r에 기록하고, 아니라면 r[현재 인덱스] - r[처음 인덱스]를 한다. 이것이 최대 길이이다.

## **💭 오늘의 회고**

누적합은 항상 1-indexed를 사용해야 함을 배웠다.
